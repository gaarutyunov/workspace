## 2. `internal/registry` — lift discovery and the remote fetch out of `internal/cli` and `internal/skillfile`

Before the catalog, because the catalog consumes it and a move mixed into new
code is a move nobody can review. **Since the catalog moved to `epos-registry`
(D2), this section is load-bearing rather than tidy**: `cmd/epos-registry` must
not import `internal/cli` (that links the whole CLI) and must not import
`internal/skillfile` (that links `go-git`, `goawk`, `go-gitdiff` and
`goccy/go-yaml`). `internal/registry` is the package that lets the registry
binary talk to a registry without becoming the CLI.

- [ ] 2.1 Move `registryClient`, `ociRegistry`, `newOCIRegistry`, `discover`, `skill`, `matches`, `withinNamespace`, `unsupported` and `errNoCatalog` from `internal/cli/discover.go` to a new `internal/registry` package, exported. Move the tests and the mockgen directive with them.
- [ ] 2.1a **`registryOptions` does not move** (**D2**). It lives in `internal/cli/credentials.go`, carries the cobra flag binding and the Docker credential store, and is shared by `pull`, `push`, `build`, `sign` and `install`. `internal/registry` defines its own plain options struct — plain-HTTP, a credential resolver, a client — with no cobra and no koanf in it; `internal/cli` builds one from `registryOptions`. Keep `explain`/`explainAuth`'s messages identical: they are the user-facing text for an auth failure.
- [ ] 2.2 `internal/cli/list.go` and `search.go` call into the new package. **Assert byte-identical output**: the godog features covering `epos list` and `epos search` must pass unchanged, and their expected output must not be edited in this task. If it has to be, the move was not a move.
- [ ] 2.3 **Move** the remote fetch-and-unpack routine the detail page needs — do not export it where it stands. It is **`skillfile.fetchOCIBase`** — resolve, fetch the manifest, assert exactly one layer, fetch it, untar (**D3c**). Not `install.read`, which reads the *local store*; not `ociTreeFiles`, which takes bytes already in hand. It lands in `internal/registry` returning an in-memory file map, and `internal/skillfile` builds its `Tree` from that map and keeps the `Tree` type. It keeps `checkPath`, the symlink/hardlink rejection and the 64 MiB cap — the catalog points at arbitrary registries, so the exposure is larger than the Skillfile `FROM` this was written for, not smaller.
- [ ] 2.3c **The reason it moves rather than being exported: `epos-registry` must not link `internal/skillfile`** (**D2a**). Assert it — a test that enumerates the registry binary's transitive imports and fails on `internal/skillfile`, `internal/cli` and `internal/install`. Without the assertion this decision survives exactly until the first convenient import. `go list -deps ./cmd/epos-registry` is the whole mechanism.
- [ ] 2.3d Confirm `epos build` still produces byte-identical artifacts for an OCI `FROM` after the move. The tar reading is the same code in a different package; if a `Tree` built through the file map differs in ordering or mode handling, SPEC §2.4's determinism promise breaks and the Skillfile tests are where it shows.
- [ ] 2.3a **`fetchOCIBase` carries no credential today** — it takes a reference and a plain-HTTP bool, while the list path goes through `newOCIRegistry`, which does present stored credentials. Exported unchanged, the catalog's list pages would render against an authenticated registry and every detail page would 401. Widen the signature to accept the same credential-bearing client the list path uses — which incidentally gives Skillfile `FROM` an auth path it does not have — or decide that the catalog is anonymous-read only and say so in the command's help. Do not discover this on the first private registry.
- [ ] 2.4 **The manifest read the catalog model needs does not exist yet.** `ociRegistry.Annotations` returns annotations only; task 5.1 needs the config descriptor's inline `Data` and the layer descriptor as well. Add it to `internal/registry` beside `Annotations` — one method returning the manifest's relevant parts — rather than letting `internal/catalog` reach past the package for it.

## 3. The persistent statistics path — the span, the collector, the schema

**Read design D4 first**, especially **D4a** (why a span and not a metric) and
**D4b** (the schema, which this change defines rather than discovers). This
section reverses a decision an earlier draft made the other way and then
reshapes it again after the second review. `epos-registry`'s **relay path**
still holds no state and no database credential — if you find yourself writing
either, re-read **D4g**.

- [ ] 3.1 Add a tracer provider to `epos-registry`, selected by a new `traces.exporter` key (`none` by default, `otlp` to enable) resolved through the koanf tree `loadConfig` already builds. The existing `metrics.*` keys and the `stdout`/`none` metric exporters keep behaving **exactly** as they do; nothing about `epos.downloads` changes (**D4a**, **D4h**).
- [ ] 3.1a Emit one `epos.download` span from the **same call site** that increments the counter — one function, one attribute set, used by both. This is what makes "one instrumentation path" true and what stops the two describing different events. Do not add a second recording site and do not wrap the HTTP handler in `otelhttp`: server instrumentation records `http.user_agent` as a matter of course and would reintroduce exactly what 3.4 removes (**D4c**).
- [ ] 3.1b **Sample always, deliberately.** `AlwaysSample` for this span, with a comment saying that changing it silently changes every number the catalog renders. A sampled count is a wrong number presented as a right one (**D4a**).
- [ ] 3.2 Choose `otlptracegrpc` or `otlptracehttp` on firewall-friendliness, **not** on weight — task 1.6 measures why. Endpoint, headers, protocol and timeout are koanf keys beside the existing metrics keys.
- [ ] 3.3 Exporting must not block a request or fail one. A collector that is unreachable costs telemetry, never availability — assert it with a test that points the exporter at a dead address and checks the registry still serves.
- [ ] 3.4 **Drop the `client` attribute in both directions (D4c).** On the metric, `sdkmetric.NewView(Instrument{Name: "epos.downloads"}, Stream{AttributeFilter: attribute.NewAllowKeysFilter("repository", "verified", "version")})` registered with `WithView` — an **allow**-list, not a deny-list, applied unconditionally. On the span, never set it: the shared attribute builder from 3.1a is the mechanism, because there is no span-side equivalent of a view.
- [ ] 3.4a Turn exemplars off, or filter them: the SDK documents that a view's filtered-out attributes may still ride on exemplars, which would defeat 3.4 silently.
- [ ] 3.4b `tests/integration/steps_counting.go` is the only place in the repository that reads `client`. Update it, and note in the pull request that this is the argument for dropping the attribute everywhere rather than only where it is dangerous.
- [ ] 3.5 Check in the collector configuration — an OTLP receiver and the contrib `clickhouseexporter` on its **traces** pipeline — plus a compose file that stands up collector + ClickHouse for local development. Pin every image. **Apply the DDL before the collector starts**, in the compose file and in CI: a materialized view sees only rows inserted after it exists (task 1.5a).
- [ ] 3.5a **Check in the schema itself** — `epos_downloads_total`, `epos_downloads_mv` and the grants — as one reviewed `.sql` file, exactly as **D4b** and **D4g** write it. It declares only this project's own objects: `otel_traces` is the collector's and is neither created nor altered here. Carry the backfill `INSERT … SELECT` as a comment (task 1.5a) and a comment on the table saying reads must `sum()` (task 1.5b).
- [ ] 3.5b **Three principals, three privileges (D4g).** The collector's user gets `INSERT` on the collector's tables; the catalog's user gets `SELECT` on `epos_downloads_total` and nothing else, under a read-only profile bounded by `max_execution_time` and `max_result_rows`; the relay gets **no database credential at all**. Declare all three in the same `.sql` file so the separation is reviewable.
- [ ] 3.6 **Do not write ClickHouse DDL from Go, and do not insert into ClickHouse from anywhere in this repository.** The rollup is schema; the raw tables are the collector's; epos reads. A ClickHouse write client appearing anywhere means **D4f**'s rejected alternative got built by accident, and it is also how the relay acquires the write credential **D4g** exists to deny it.
- [ ] 3.7 `SPEC.md` §5.3: record the `epos.download` span as the durable record, with its attributes; amend the attribute list to drop `client`, with the reason (**D4c**). **`otlp` and `prometheus` stay unimplemented as metrics exporters** — say so, because an earlier draft claimed implementing `otlp` completed the table. Leave §4.5, §5.1 and §5.2 alone.
- [ ] 3.7a `SPEC.md` §4.4 and §15 decision #2 — **this is the amendment the previous draft cited as the reason not to do any of this**, so it needs writing carefully (**D2a**). #2 gains: a read-only HTML catalog may be served on the same listener under a reserved prefix, off by default, and is not a second *API* surface. §4.4's prohibition is scoped to the relay path, its "any request may land on any replica" sentence kept word for word, with the catalog's index named as process-local, in-memory, rebuilt at startup and shared with nothing. **Decision #3 is not amended** — it is about rendering a skill's values templates at install, not about HTML — and the pull request says so, because it was misread once already.

## 4. The catalog's statistics source

- [ ] 4.1 `Stats` — one context-taking method returning `Counts` (`CapturedAt`, and per-repository `Verified`/`Unverified`). One type serves as the on-disk JSON shape, the query-result shape and the in-memory shape, so there is no converter and no second schema (**D4e**).
- [ ] 4.1a **The repository set is a constructor argument, not a method parameter** (**D4e**). `NewClickHouseStats(db, repos, ttl)`; the index supplies `repos`. Without it the `clickhouse` source returns every repository the collector has ever seen, including ones this catalog does not list. `file` filters its rows to the same set so all three sources answer the same question.
- [ ] 4.2 `none` — the default, and a **supported configuration rather than a degraded mode** (**D4h**). The pull column is **absent**, not zero; the home page is a deterministically ordered index and says so, with no rank column and no wording implying popularity. Test that the rendered page contains no count column at all. Decide and state whether `none` is a type or simply a nil `Stats` handled at one call site; either is fine, an implementation that does both is not. The difference between the two shapes is which sections the renderer emits — not a second renderer, template set or route table.
- [ ] 4.3 `clickhouse` — run the `SELECT` **D4b** writes out, against `epos_downloads_total`, for the repositories the source was built with, grouped by repository and `Verified`. `sum()` is required, not decorative (task 1.5b). `github.com/ClickHouse/clickhouse-go/v2`, the **read-only** credential from 3.5b, a bounded timeout. Do not query `otel_traces` directly: it expires, and the encoding of `verified` belongs in the view (**D4b**'s rejected alternative).
- [ ] 4.4 `file` — read and validate the JSON. A malformed file is rejected whole with the filename in the error, never half-read into partial counts.
- [ ] 4.4a The store DSN is the koanf key `catalog.stats-dsn`, reachable from `EPOS_REGISTRY_CATALOG_STATS_DSN` or a file the configuration names — and **there is no flag that accepts it** (**D4e**, **D2b**). A server runs for days and its arguments are readable by every process on the host. Since the catalog joined `epos-registry`'s koanf tree this is an ordinary key rather than an exception to a flags-only rule.
- [ ] 4.4b The DSN's credential must be one that cannot write (3.5b). Assert it in the integration tier: point the catalog at the store with the catalog user and confirm an `INSERT` from that connection is refused. "The catalog only reads" is a grant, not a convention (**D4g**).
- [ ] 4.5 **Counts are read per request in the served catalog** (**D4e**), behind a short TTL cache and a timeout. Make the TTL configurable and default it small; the end-to-end assertion in section 14 sets it to zero rather than sleeping. This is what makes "pull, refresh, the number moved" true, and it is why fixing the *index* at startup (**D3b**) is a separate decision.
- [ ] 4.5b **A slow store must not reach the relay.** The catalog now shares a process with `/v2/`, so assert directly: with the store unreachable or hanging, distribution API latency is unaffected and every catalog page still serves without counts (**D4e**, **D4g**). This is the hazard the move created and it is not covered by 4.7, which is about the catalog alone.
- [ ] 4.5a **The cache is a lazy refresh on the request path under one mutex — not a background goroutine** (**D4e**). No owner to name, no shutdown path to thread through `srv.Shutdown`, no `-race` story on three platforms. Holding the mutex across the query serialises a stampede; if that proves too coarse the next step is `singleflight`, which is still not a goroutine. `--catalog.stats-ttl=0` must mean "query every request", exactly.
- [ ] 4.6 `export` queries once and writes the numbers into the pages with the capture time.
- [ ] 4.7 A failing source degrades: every page still serves, counts go absent, the failure is logged, nothing renders as zero. Test with an unreachable store, a missing file and a truncated one.
- [ ] 4.8 Unknown ≠ zero. A skill with no row renders as unknown. This is a rendering rule as much as a data one; assert it in the renderer test.
- [ ] 4.9 The catalog only reads. No credential that could write, no DDL, no insert.

## 5. `internal/catalog` — the model and the renderer

**`internal/catalog` is imported by `cmd/epos-registry` and by nothing on the
CLI's side of the graph** (**D2**). That is the deliverable of the owner's first
review comment, and task 7.3a is the assertion that keeps it true.

- [ ] 5.1 The model: what a page needs, built from a manifest, its inline config, its provenance annotations, its values schema where present, and (for a detail page) its content layer. **One entry per repository, not per version** (**D3a**) — the counter's only key is the repository. No registry types in the template data; the renderer must be testable with a literal.
- [ ] 5.2 The route table, shared by both drivers (**D2**): home (leaderboard), catalog list, skill detail, tools. `export` walks it; `serve` serves it. One test asserts the two produce identical bytes **for the same base path, model and counts**, and a second asserts a different base path changes only the prefix (**D2b**).
- [ ] 5.3 `html/template` for every page. Server-rendered; the browser receives finished HTML. Rendered Markdown enters as pre-sanitised HTML from section 6, at one place — do not scatter `template.HTML` through the templates.
- [ ] 5.4 The detail-page cache: keyed on manifest digest, which is immutable, so there is no invalidation path to get wrong. Bound it. Note this is the *content* cache and is unrelated to 4.5's counts TTL.
- [ ] 5.5 A skill whose layer cannot be read, is oversized, or is hostile still lists, and its detail page says the document could not be read. Do not fail the catalog for one bad artifact — that is a page an attacker can take the site down with.
- [ ] 5.6 The provenance section from `dev.epos.skillfile.stages` (task 1.2): files grouped by contributing stage, plus base name/digest and Skillfile digest. Omit the whole section when the annotation is absent — an empty provenance table is worse than none.
- [ ] 5.7 The served catalog answers only for repositories in the index built at startup; anything else is a 404 with no registry request (**D3b**). Without this the catalog is a fetch-anything proxy wearing a UI — and it is now a proxy bolted to a registry, so the stakes are higher than they were. Say in the help that the index is fixed until restart **and that the counts are not**.
- [ ] 5.7c **A failed index build must not stop the registry** (**D2a**). Bring the listener up first; build the index as a startup step whose failure is logged and whose result is an empty catalog serving a page that says so. `epos-registry` starts today without ever contacting upstream, and enabling the catalog must not turn an upstream blip at boot into a registry that will not serve `/v2/`. Assert it: start with an unreachable upstream and confirm the relay serves.
- [ ] 5.7a **`/v2/` is matched before any catalog route, and no catalog route may shadow one.** Refuse a base path of `/v2` (or anything under it) at startup rather than discovering the collision in production. Assert with a test that every distribution API path still routes to the relay with the catalog enabled at `/` (**D2c**).
- [ ] 5.7b Nothing the catalog holds is consulted to answer a distribution API request, and nothing it holds is written to disk. The index is in memory, rebuilt at startup, shared with nothing — that is what keeps §4.4's amendment narrow (task 3.7a). Assert the "no disk" half; it is the one an implementation is most likely to break with a cache directory.
- [ ] 5.8 Thread `context.Context` through the model build, every registry fetch, `Stats.Pulls` and both drivers. `serve` gives each request-scoped layer fetch and each statistics query its own timeout; `export` runs under one deadline (**D12**). Retrofitting this later means changing every signature.
- [ ] 5.9 The values-contract section (**D11**): a table of declared parameters when the artifact carries a schema, nothing at all when it does not. The schema's strings are publisher-authored — escape them like any other untrusted input, and fail only that section on a malformed or oversized schema.

## 6. Markdown — the security boundary

Written as its own section because design **D7** is the one place in this change
where getting it wrong is not a cosmetic defect.

- [ ] 6.1 Add `github.com/yuin/goldmark` (v1.8.5 at the time of writing; **v1**, not the v2 beta). Pure Go, no cgo (SPEC §1.2), and its whole build closure is one module. Enable `extension.Table` (or `extension.GFM`) — `SKILL.md` documents use tables freely. Confirm `govulncheck` stays green; it is a required CI job.
- [ ] 6.2 Render with raw HTML **off** (goldmark's default; the requirement is that it stays off and that a test proves it) and constrain link, image and autolink schemes to `http`, `https`, `mailto` and relative, **as an AST transformer** — before any HTML string exists (**D7**). Note that a `javascript:` or `data:text/html` Markdown link is **not** raw HTML and survives "disable raw HTML"; it must be defanged explicitly. Do not hand-write an HTML sanitiser; if an output-side pass proves necessary, use `bluemonday` and say in the pull request what the transformer could not reach (**D7a**).
- [ ] 6.3 Strip the frontmatter before rendering. `artifact.ParseFrontmatter` already finds its extent; the body starts after it. Do not add a frontmatter extension for code the repository already has.
- [ ] 6.4 Relative links: **the catalog serves no route that can hold a file out of a content layer** (**D2**'s route table is home, list, detail, tools), so in practice every relative link renders inert. Implement the inert branch, and say in a comment that the "resolve to something we serve" branch is unreachable until a route exists — an implementor should not spend an afternoon looking for the route.
- [ ] 6.4a Cap the rendered document's size independently of the 64 MiB layer cap (**D7**). An enormous but legal `SKILL.md` is parsed and rendered on every request otherwise; the digest-keyed cache is bounded and so is mitigation rather than a fix. Oversized ⇒ the skill still lists, its page says the document could not be rendered.
- [ ] 6.4b No heading anchors (**D7**). Rendered headings are not linkable; that is a decision, not an oversight, and one line of comment keeps it one.
- [ ] 6.5 A hostile fixture corpus, asserted: raw `<script>`, an `<img onerror>`, an inline SVG with a handler, an `<iframe>`, a `javascript:` link, a `data:text/html` image, and a document that is nothing but frontmatter. Each asserts on the **rendered output**, so a later configuration change that re-enables passthrough fails the build.
- [ ] 6.6 Assert the expressive path too — headings, nested lists, tables, fenced code, blockquotes, ordinary links all render. A sanitiser that eats the content is a different bug with the same cause.
- [ ] 6.7 No syntax highlighting (**D7a**). Fenced code is `<pre><code>` styled from the kit's tokens. If it is added later it is `chroma` + `goldmark-highlighting/v2`, and the pull request that adds it has to weigh chroma's embedded lexers and that glue module's never-tagged status.

## 10. The values schema and the inference command

**Scope note, and it needs the owner's answer before this section starts.**
Design **D14d** recommends this section be delivered under **epos#47** — the
issue whose subject is already what type a value has, and whose approach a
declared schema supersedes — rather than inside a frontend change. It is
specified here because the owner asked for it here. Under either answer the

- [ ] 10.1 The schema format (**D14a**): `values.schema.json` at the skill root, an OpenAPI 3.1 Schema Object — which is a JSON Schema 2020-12 document, so a general validator accepts it. **Structural**: root is an object, every declared path has a declared type. No CRD envelope — no `apiVersion`, `kind`, `versions` or conversion. Write down the subset of keywords epos honours (`type`, `properties`, `required`, `default`, `description`, `enum`, `items`, `additionalProperties`) and which it deliberately ignores.
- [ ] 10.2 Scoping mirrors `install.Values.Scope` (**D14a**): the skill's own parameters at the top level, a property per contributing stage, and `global`. A schema that does not mirror the renderer validates a document nobody renders.
- [ ] 10.3 Carry it in the artifact (**D14b**): the file in the content layer, and a copy on the manifest as the annotation **`dev.epos.values.schema`**, so a catalog reads it from one manifest GET. The copy is written *from* the layer at pack time — never authored twice. Above the cap from task 1.11, omit the annotation and record with a marker that a schema exists in the layer, so "no schema" and "too large to annotate" stay distinguishable.
- [ ] 10.3a **Do not put it in the config blob.** SPEC §2.1 makes "the config blob mirrors `SKILL.md` frontmatter" an invariant and `artifact.assemble` derives it from `ParseFrontmatter` alone; §2.2 says an epos extension must never alter the skill artifact. A `dev.epos.*` annotation is the mechanism §2.3 already provides for exactly this — `dev.epos.skillfile.stages` is a JSON document carried the same way — and it leaves §2.1 untouched. If the annotation cap proves too tight, the fallback is a frontmatter key (mirrored into the config for free), **not** a bespoke config key.
- [ ] 10.4 Validate at install with `github.com/santhosh-tekuri/jsonschema/v6` (task 1.10). Validate the **merged** values, after files and `--set` have been combined — a file supplying half a required object and a flag supplying the other half is valid. Normalise through JSON before validating: the library takes plain JSON values, and feeding it YAML-derived or Go-typed maps misbehaves (Helm wraps the same call in a `recover()` for this reason; normalising is the better answer).
- [ ] 10.5 Apply declared defaults before rendering, so a default lives in the contract rather than in every template that reads the value.
- [ ] 10.6 **Fix `--set`, which is epos#47's actual defect.** `applySet` in `internal/install/values.go` stores every value as a string, so `--set openapi=false` is truthy and silently disables nothing. With a schema, the **declared type wins** — `--set version=1.0` against `type: string` stays `"1.0"`. Without a schema, infer the way helm's `strvals` does (`false`/`true` → bool, integers → number, `null` → nil), with **`--set-string`** as the forcing form, taking helm's name so the knowledge transfers. A value that cannot be coerced is an error naming the parameter and both types — never a zero value. `-f` and `--set` must agree.
- [ ] 10.6a **This is a behaviour change and must be announced (D14e).** `--set version=1.0` becomes a number and renders as `1`; `--set x=null` becomes nil; assertions in `internal/install/values_test.go` change. Say so in the pull request and in the generated CLI reference, naming `--set-string` as the migration. Do not ship it as a silent improvement.
- [ ] 10.6b Replace `applySet`'s doc comment rather than deleting it. It currently records the opposite decision *with its reason* ("Values stay strings. Helm infers types here; this does not…"). The next reader should find that the decision was reversed and why — the reason it gave, that a value silently promoted to a float is worse than a literal string, is exactly the failure `--set-string` and the declared type now cover.
- [ ] 10.7 `epos values schema <path-or-ref>` (**D14c**): **one positional argument, `cobra.ExactArgs(1)`, always local** — a skill directory (no stages exist, so the schema has the skill's own properties and `global` only) or a reference into the local store (stage scoping read from that artifact's `dev.epos.skillfile.stages`). **It does not take a Skillfile**: attributing stages from a recipe means resolving its `FROM`, and an OCI or git `FROM` is registry access, which would make an inference command a network command. Then walk each template's `text/template/parse` tree — **parse, never execute**. epos gives `text/template` no custom functions (SPEC §10.3), so there is no function map to stub. Collect `*parse.FieldNode` with `Ident[0] == "Values"`, carrying a stack of enclosing `*parse.IfNode` / `*parse.RangeNode` / `*parse.WithNode`. Rules: string by default; boolean when the value is the pipeline of `if`/`else if`/`with` or an argument to `not`/`and`/`or` within one; integer or number when it is an operand of a comparison against a `*parse.NumberNode`; array when it is the subject of `range`; object when referenced only through sub-fields.
- [ ] 10.7a **The two things that make this wrong quietly**: `with` and `range` rebind dot, so `.tag` inside `{{ with .Values.image }}` is `.Values.image.tag` and scope must be tracked; and `*parse.ChainNode` carries fields hung off a parenthesised expression. There is no traversal helper in the standard library (golang/go#56404 is open for exactly this) and no library that already does it — this is a walker to write, and it is where the tests in 13.2 earn their keep.
- [ ] 10.7b The command emits a **draft** and says so. It refuses to overwrite an existing schema unless told to, and can instead report how the inferred schema differs from the committed one. Contradictory usage — one path used as a condition *and* compared to a number — is reported with both source positions, never resolved by precedence. State the limit in the output: `{{ if .Values.x }}` is as true for a non-empty string as for `true`, so the boolean rule is a heuristic (**D14c**).
